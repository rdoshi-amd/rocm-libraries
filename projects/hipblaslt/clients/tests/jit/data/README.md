# Pre-generated JIT test bundles

Each directory under `gfx950/` is one source bundle: the input a JIT backend
returns and the comgr builder builds. The JIT tests build and load these
bundles, so they need neither Python nor a generator.

| Path | Contents |
| --- | --- |
| `library/TensileLibrary.dat` | The one-solution library entry (MsgPack, uncompressed) |
| `sources/<kernel>.s` | The main kernel assembly; exactly one |
| `sources/Kernels.cpp`, `sources/Kernels.h` | Helper kernel source, when the solution needs helpers |
| Other `sources/*.h` files | Headers that `Kernels.cpp` includes |
| `manifest.json` | Provenance; hipBLASLt does not read it |

The manifest names the main kernel (`main_kernel.name`), the solution, the
library path and format, and the sources. Its `provenance` object records
`source_revision`, `generator_version`, `compiler_version`, `code_object_version`,
`kernargs_version` and `persistent_loop_args_version`.

| Bundle | Problem and execution policy | Generator command |
| --- | --- | --- |
| `gfx950/plain` | FP16 A, B, C and D, FP32 compute, A and B not transposed; one wave64 per 16x16 tile, K in steps of 16, no prefetch; GlobalSplitU=1, TileProcessingStrategy=None; no helper kernels | `python -m Tensile.SingleSolution ../clients/tests/jit/data/plain.yaml OUT --architecture gfx950 --cxx-compiler amdclang++ --source-only` (`OUT/bundle`) |
| `gfx950/splitk` | The same data types; generated for M=256, N=128, K=512; GlobalSplitU=4 with MultipleBuffer, TileProcessingStrategy=None; helper kernels that reduce the partial results (`Cijk_SH_PostGSU16_VW4`, `_VW2` and `_VW1`) and apply beta (`Cijk_H_GA`) | `python -m Tensile.SingleSolution ../clients/tests/jit/data/splitk.yaml OUT --architecture gfx950 --cxx-compiler amdclang++ --source-only` (`OUT/bundle`) |
| `gfx950/streamk` | The same data types; generated for M=256, N=128, K=4096; TileProcessingStrategy=StreamK, WorkAssignment=StaticGrid, StreamKAtomic=0 | `python -m Tensile.SingleSolution Tensile/Tests/unit/test_data/single_solution_streamk.yaml OUT --architecture gfx950 --cxx-compiler amdclang++ --source-only` (`OUT/bundle`) |
| `gfx950/amax` | The same data types; generated for M=256, N=128, K=128; OutputAmaxD, GlobalSplitU=1, TileProcessingStrategy=None | `python -m Tensile.SingleSolution Tensile/Tests/unit/test_data/single_solution_amax.yaml OUT --architecture gfx950 --cxx-compiler amdclang++ --source-only` (`OUT/bundle`) |

The files are TensileLite output (MIT licence), generated by the commands above
from the recipe each command names and the TensileLite sources at each
manifest's `source_revision`; `plain.yaml` and `splitk.yaml` are in this
directory, and the manifest's `provenance.config_sha256` is the SHA-256 of
the recipe. The commands run in
`projects/hipblaslt/tensilelite` with `OUT` a fresh directory and `PYTHONPATH`
naming the `tensilelite/rocisa` and `tensilelite` directories of a
hipBLASLt build and then `projects/hipblaslt/tensilelite`; the bundle is the
named directory under `OUT`. Each bundle is copied without symbolic links, and
`provenance.compiler_path` is removed from its manifest. The generator writes
the library entry compressed, as `library/TensileLibrary.dat.zlib`; it is
stored inflated as `library/TensileLibrary.dat`, and the manifest's
`library.path` names that file.

## When the freshness test fails

The `jit-bundle-freshness` CTest test, `hipblaslt-jit-bundle-freshness-test`,
fails when a bundle's `kernargs_version` or `persistent_loop_args_version`
differs from `KernArgsVersion` or `PersistentLoopArgsVersion` in
`tensilelite/Tensile/Common/GlobalParameters.py`, when its `code_object_version`
differs from the version the JIT builder uses, or when the host library
cannot read its library entry or comgr cannot build its sources. The committed
bundles are then stale. Regenerate every bundle with the commands above, update
the bundle table, and commit the bundles with the change that made them stale.
